# 鬼打架 · 硬件价格监测

以 macOS 为默认部署环境的本机价格监测系统，网页与免依赖 Cookie 导出工具支持 macOS / Windows。默认以 **Crawlee + Playwright 爬虫**采集淘宝/天猫商品 DOM，可在「设置 → 价格来源」切换到淘宝 / 京东官方 API。两条分支互斥，不互相兜底；官方 API 默认关闭。失败价格为 Python `None` / JSON `null`，历史有效价保留并注明。

> 本项目用于个人价格记录与学习研究。请遵守淘宝、天猫、京东的服务条款、访问频率限制及所在地法律，不要用于商业转售、绕过验证或高频抓取。

## 在 Mac 上使用

1. 双击 **启动监测.command**，首次运行会自动创建虚拟环境并安装依赖。若提示管理员尚未创建，在项目目录执行 `.venv/bin/python tools/manage_accounts.py create-admin`，按终端提示设置管理员密码，然后再次启动；浏览器会打开 http://127.0.0.1:8765。
2. 进入 **设置 → 淘宝账号**，选择服务器 Mac 上的 Edge 或 Chrome，点击「在服务器 Mac 登录」。
3. 在弹出窗口登录淘宝，回到系统点击 **完成登录并保存**。
4. 在商品库添加淘宝/天猫完整商品链接，开始自动监测。

通过公网远程访问时，「在服务器 Mac 登录」仍在运行服务的 Mac 上打开窗口，完成后点击「完成登录并保存」供采集复用。另有「在本设备打开淘宝登录页」入口，在当前手机或电脑打开淘宝；该设备的 Cookie 不会自动同步到服务器，不能替代服务器登录。

首次安装需要 Python 3.10+、Node.js 20.19+。脚本自动创建虚拟环境、安装依赖和构建前端。已安装好依赖与构建产物时直接启动。Edge/Chrome 使用本机版本；选择 Chromium 时先运行：

```sh
.venv/bin/python -m playwright install chromium
```

关闭网页、终端后后台仍运行。双击 **停止监测.command** 停止。Mac 休眠、关机期间不能采集，唤醒后补采最新价，不补造历史；电脑重启后重新双击启动脚本。

```sh
.venv/bin/python run.py                 # 后台启动并打开网页
.venv/bin/python run.py --stop          # 停止
.venv/bin/python run.py --foreground    # 前台运行，便于调试
```

如果 macOS 未将 `.command` 关联到终端，可右键「打开方式 → 终端」，或执行 `zsh 启动监测.command`。

## 页面与功能

前端按照提供的 13 页线框图组织：

- **总览**：关注商品、趋势分布、降价榜、提醒、健康度与事件。卡片排序、宽度配置、移除/添加、视图保存。
- **商品库**：名称/型号/标签搜索，品类、分组、库存、店铺、趋势、价格筛选，列设置、批量操作、导入导出、双击编辑。
- **商品详情**：阶梯价格图、时间范围、原始/有效价、划线价、事件/点/区间标注、价格点操作、框选批量标无效、手动补价、修正撤销、变价事件、预测回顾、提醒、备注和修改历史。
- **比较页**：多商品/规格与同款各店铺，绝对价格/百分比变化/建议价比例，基准店铺、最低价包络线、图片/数据导出、视图保存。
- **提醒**：目标价、窗口降幅、窗口新低、到货、大促前提醒；范围、连续确认、冷却、模板、历史模拟、投递记录与重试。
- **事件日历**：月历、全年时间线、拖动平移日期、编辑起止日期、作用范围、置信度、得知时间、候选确认、固定日期参考、导入导出。
- **采集管理**：持久队列、手动/定时采集、暂停恢复、频率、重试、熔断/探测、异常价隔离、日志、任务与活动期加密采集。
- 采集成功、失败都会在当前打开的页面弹出结果窗口，展示商品、采集价或失败原因，并可展开诊断。并发完成的结果集中展示，点击「知道了」后不重复提醒；首次打开不补弹旧历史，未确认的结果刷新后仍可查看。离线后恢复连接会继续读取期间完成的任务。
- **预测中心**：规则参考、数据充分性判定、阈值预览/重算、影子记录、到期回顾、临时展示覆盖。
- **审计/回收站**：修改差异、单次/批量/时段回滚、冲突检查、软删除、恢复与永久删除。
- **设置**：会话、视图、深浅/系统主题、表格密度、图表默认、通知、免打扰、数据口径、保留策略、备份和令牌。

站内提醒始终可用。Bark、Server酱、企业微信、飞书、邮件需配置接收地址/邮箱；免打扰期间外部通知排队。

事件入口为手动、固定日期生成和导入，不内置新闻订阅源。固定日期仅为待确认参考，实际活动窗口按公告核实。

## 数据与采集口径

- 数据库金额为**整数分**，前端显示元。手工价格录入接口接收元，导出的价格记录带 `price_unit: cent`。
- 原始观测只追加；修正与无效标记使用覆盖层，支持查看原值和撤销。
- 商品详情 →「按天编辑价格」可按北京时间选择日期、价格口径，编辑或补录某一天的历史价。日价格只覆盖当前商品 / SKU / 价格口径；同日新采集继续保留人工价格，原始金额不改写。填写修改原因后保存，图表和统计同步更新；撤销后恢复观测，无观测日期的补录点移除。日价格保留审计历史与版本冲突保护；有效的人工编辑、补录、修正价格视为真实价格，与采集价格一样参与模型训练、未来最低价标签与预测。
- 失败返回 `null`，不写零元、不清空上次有效价。
- 每个账号各自最多 5 个商品并发采集；所有普通用户合计最多 50 个，满额任务保留排队并在名额释放后继续。管理员独立计算，不占这 50 个名额。可在「采集管理 → 采集策略」设为 1–5。每个任务使用独立爬虫进程及 Cookie 副本，采集间隔分别作用于各并发名额。单次采集超过 120 秒会强制终止爬虫与浏览器子进程，记为超时并返回 `null`，不自动重试；其他任务继续运行。刷新后的 Cookie 原子合并保存，不覆盖重新登录的会话。
- 商品库和采集管理均提供「一键采集全部」：对当前价格来源支持的有效商品链接立即采集一次，包含已暂停自动监测的商品，但不会更改其自动监测开关。每批最多 5 个并发（遵循更低的并发设置），整批结束后等待固定 8 秒再启动下一批，末批不足 5 个也会执行。已有排队任务复用，运行中的任务不重复创建；重复点击不会叠加未完成的批次。无链接 / 无效链接会跳过并显示数量。批次和冷却状态持久保存，服务重启后继续；登录状态和熔断保护仍生效。
- 暂停、熔断及历史 Cookie 校验失败只拦截自动采集。一键采集、单商品立即采集、批量重抓、手动重试和 Cookie 校验优先执行，包含已暂停自动监测的商品；使用当前账号最新的 Cookie，缺失或无效时正常返回失败结果，不会一直等待校验。人工任务不会清空自动采集的暂停或熔断设置，执行后也不会自动恢复定时采集。来源互斥、并发上限、启动间隔、每批 8 秒间隔及 120 秒超时仍然生效；删除商品或取消排队任务仍会终止对应任务。

- 爬虫对同一账号的商品启动增加统一间隔，默认至少 5 秒并带 0–1.25 秒随机间隔；页面读取仍可重叠，最多 5 个并发，一键采集仍保留每批最多 5 个和批次之间 8 秒间隔。不同账号独立限速，官方 API 分支不受此启动间隔影响。排队等待不计入浏览器的 120 秒时限，在「采集管理 → 最近任务」显示等待原因及已知启动时间。「采集管理 → 采集策略」可调整同账号启动间隔（1–120 秒），也可选择在服务器 Mac 显示真实采集浏览器窗口。
- 登录与采集使用相同的中文语言、上海时区、1440×900 视口及所选浏览器原生身份，不随机切换浏览器身份或设备参数。商品页和登录页的验证码、滑块或访问限制首次出现即返回 `blocked`，不自动重试，并暂停该账号尚未打开页面的任务；不会清除 Cookie，也不会影响其他账号。需要人工验证的状态在重启后保留，完成验证并保存会话后先进行 Cookie 校验。页面请求节奏的调整不能保证平台不再要求验证。
- 「采集管理 → 解除熔断」可手动结束冷却并清零连续失败计数，不会额外发起探测或取消全局暂停。登录失效仍需重新登录；之后再次达到失败阈值仍会熔断。
- 隐藏金额、区间价、解析冲突、验证页、登录失效、超时不猜测价格。
- 带 `skuId` 时需要页面 SKU 或「预期选中规格」核对。仅 URL 保留 SKU 不能证明规格正确；核对失败为空价，商品详情展示实际读到的选中规格。
- 默认不把券后/会员价计入常规价格线，可在数据口径中启用，原始观测一直保留。
- 异常价进入待确认，人工核实后确认有效；确认前不触发降价提醒。
- 最低价指**监测以来**或明确窗口的最低价，不含监测开始前的未知数据。
- 默认新价连续两次一致才确认变价，失败打断确认序列。
- 同款店铺归组依据统一的型号、规格；不同容量、版本、盒散分别处理。
- 导入先预览再写入，重复/无效项跳过。导入的商品默认暂停，避免大量并发请求。

## Cookie 与本机凭据

采集失败时，可在「采集管理 → 最近任务 → 查看详情」查看失败阶段、HTTP 状态、页面标题、价格区域原文、目标/页面 SKU、实际选中规格、异常代码和每次重试结果，并下载诊断 JSON。日志与商品价格记录也保留同一份诊断；旧记录没有的现场信息不会补造。

爬虫支持新版 SKU 面板价格 DOM，并通过页面已加载的 SKU 映射和实际选中选项核验规格。价格只取可见页面金额，不使用价格 API 兜底。价格区域缺失、验证页、网络异常等原始错误不会被 SKU 未核验状态覆盖。

管理员登录状态保存在 `data/auth/taobao.json`，普通用户会话保存在 `data/users/<用户ID>/auth/taobao.json`，包含 Cookie 和浏览器登录存储，权限 `0600`。原目录已有 `session.json` 时启动会导入。重启自动复用有效会话，平台使其过期时仍需重新登录。

管理员与普通用户采用相同的 Cookie 更新规则：以服务器实际接受新会话的顺序为准，上传文件、粘贴 Cookie、在服务器 Mac 完成登录都写入当前账号的同一个会话文件，不设置渠道优先级。没有新会话就持续保留并复用最近保存的会话，重启也不回退到旧文件。上传时会结束尚未完成的旧登录窗口；旧采集任务不能覆盖新会话，也不能把新会话误标为失效或触发它的熔断。并发爬虫只合并实际刷新的记录，同一记录以较新启动的浏览器副本为准。主动清除会话后禁止重新导入根目录的旧 `session.json`；普通用户仍只能使用自己的 Cookie，服务器 Mac 登录只对管理员开放。平台拒绝当前 Cookie 时保留文件并提示更新，不自动换用管理员或历史 Cookie。

淘宝专用浏览器与采集进程使用直连，不继承终端的 HTTP/HTTPS 代理变量，也不会修改 macOS 系统代理。登录页加载失败时窗口保持打开，设置页会显示具体错误并提供「重试打开登录页」；尚未登录就点击完成时也可继续在原窗口登录。

默认只允许本机访问，检查 Host/Origin；本机与公网均使用账户登录和 HttpOnly/SameSite Cookie。旧令牌、旧 Cookie 和 Bearer 登录全部停用。账户密码、登录会话、淘宝 Cookie 和通知密钥不进入普通导出；数据库下载备份会清除通知密钥。

页面不展示部署设备、操作系统、设备版标识或运行目录。管理员的登录按钮使用通用名称，普通用户只使用自己的 Cookie；浏览器选择及窗口运行配置仅管理员可见和修改。诊断、历史日志、采集结果及普通价格/日志导出在返回前隐藏系统、主机名、内部路径、内网地址及浏览器运行元数据，保留错误代码、阶段、商品证据与等待原因，不修改底层记录或用户填写的名称和备注。启动脚本关闭源服务的 `Server` 响应头，健康检查只返回可用状态；接口文档仅管理员可访问。

账号数据库备份下载也会生成脱敏副本，包括旧版本创建的备份；原备份文件不被改写。普通用户的副本不包含浏览器运行配置。管理员专用的加密完整备份保留完整恢复所需的记录，仅管理员可下载。

## Cloudflare Tunnel 公网访问

示例公网入口为 **https://monitor.example.com**，Cloudflare Tunnel 服务地址保持 **http://host.docker.internal:8765**。后端仍监听本机 `127.0.0.1:8765`，无需把 8765 端口暴露到路由器。Tunnel 应保留公网 Host，请勿把 HTTP Host Header 改成 localhost。

使用与本机相同的账号和密码登录。未登录者可切换到「注册」创建普通用户；账号只需符合邮箱格式，不需要真实邮箱、不发送验证码。管理员邮箱由环境变量 `MONITOR_ADMIN_EMAIL` 配置，未设置时默认 `admin@example.com`；系统不提供新增管理员或提升权限的入口。初始密码不写入源码或文档，数据库只保存加盐的 PBKDF2-SHA256 密码摘要（600,000 次）。

各账号的数据互相隔离。服务器已有的淘宝 Cookie 仅供管理员使用，普通用户必须在自己的浏览器导出 Cookie 并上传；未上传时采集任务等待，不使用管理员会话或其他账号会话。普通用户各自保存于 `data/users/<用户ID>/`：独立 SQLite 数据库、淘宝 Cookie、设置、导入、导出、备份、日志、任务、通知及模型。后台任务、缓存和浏览器会话均按账号隔离，每个账号最多 5 个采集并发名额；普通用户共享最多 50 个名额，满额后轮流等待空闲名额，管理员不计入该上限且仍最多 5 个并发；各自批次继续遵循 8 秒间隔。管理员可以管理账号状态，但工作空间默认只读写自己的业务数据。

「设置 → 访问与安全」可修改自己的密码；修改后所有设备的旧登录立即失效。管理员还可停用 / 启用普通账号、重置普通用户密码；停用会撤销登录并停止后续调度。忘记普通用户密码时联系管理员；管理员忘记密码时，在服务器本机运行 `.venv/bin/python tools/manage_accounts.py reset-admin`，终端私密输入新密码，不修改业务数据。

默认登录有效期 12 小时，勾选「记住登录」为 30 天；右上角可退出，服务端立即撤销该会话。公网会话使用 Secure / HttpOnly / SameSite Cookie。公网 HTTP 访问自动升级到配置的 HTTPS，保留 Cloudflare Tunnel 的协议识别与来源检查；本机 `http://127.0.0.1:8765` 可用，也必须登录。注册、登录和密码管理有频率限制。

域名放行保存在 `data/public-access.json`，内容为 `{"origin":"https://monitor.example.com"}`。更换域名时同时修改这个文件中的 `origin` 和 Tunnel 的公开主机名；只接受无路径、无端口的 HTTPS 域名。删除此文件即恢复仅本机访问，配置立即生效。

后台服务使用原有「启动监测.command / 停止监测.command」管理；Mac 和 Cloudflare Tunnel 都需保持运行。淘宝登录窗口在这台 Mac 上打开，公网浏览器不会接管该窗口。保存的淘宝 Cookie 在重启后继续复用，平台令其过期后再在 Mac 上登录。

### Cookie 实际校验与排队说明

上传 Cookie 仅表示文件格式可接受、已保存。「设置 → 淘宝账号 → Cookie 实际商品校验」中，只有管理员可以选择自己已填链接的商品；普通用户只显示校验按钮，服务随机选取管理员未删除且有效的淘宝 / 天猫商品公开链接，始终用该普通用户自己的 Cookie 和队列校验。普通用户不能指定校验商品，没有自己的商品也可校验；管理员没有可用链接时会提示先添加。不会复制管理员的商品记录、历史价格、私有备注或 Cookie，也不会向普通用户返回管理员内部商品 ID。

校验显示待校验、排队中、校验中、通过、登录失效、需要验证或无法确认。无法解析价格、SKU 不符和网络超时不直接认定 Cookie 无效。单独校验不会新增历史价格或触发价格提醒，管理员复用已有采集任务时保留原采集行为；更新 Cookie 后清除旧校验结论，旧任务不能替新会话通过校验。

校验遵守每账号最多 5 个、普通用户共享 50 个名额及单次 120 秒超时。主动校验可在本账号自动采集暂停、熔断或登录过期时进行；不会自动解决短信、滑块等人工验证。

采集管理会说明每个排队任务正在等待 Cookie、登录操作、账号恢复、熔断结束、上一批完成、8 秒批次间隔、账号名额或服务器名额，并显示队列位置、已等待时间和已知恢复时间。仅可取消自己尚未开始的任务，取消不删除商品或历史价格。

### 本设备导出淘宝 Cookie（免依赖）

在「设置 → 淘宝账号」点击「下载免依赖 Cookie 导出工具」。压缩包内已包含全部扩展文件，Mac / Windows 通用，不需要 Python、Playwright、Node.js 或项目环境。需要现有的桌面版 Edge / Chrome，首次手动加载一次扩展：

1. 完整解压 ZIP；Edge 打开 `edge://extensions`，Chrome 打开 `chrome://extensions`。
2. 开启开发人员模式，点击「加载解压缩的扩展」，选择包含 `manifest.json` 的文件夹。
3. 在同一浏览器、同一用户配置登录淘宝，保持淘宝及目标天猫商品页打开。
4. 点击「鬼打架 · 淘宝 Cookie 导出」扩展，再点「一键导出 Cookie JSON」。
5. 保存文件，回到鬼打架点击「上传 Cookie 文件」。

v1.2 工具要求 Edge / Chrome 130+，仅在主动点击时读取淘宝 / 天猫 Cookie（含 HttpOnly 和分区记录），同时读取当前窗口已打开淘宝 / 天猫页面及其内嵌登录页的 localStorage，导出为兼容 Playwright 的 JSON。不读取其他网站、不自动上传。保留分区域及跨站祖先标志，不合并普通与无痕会话；提示中显示 Cookie 数量、分区数量、存储来源数量及读取警告。v1.2 修复只读取主页面、遗漏登录 iframe 的问题；会提示未读到的登录存储来源，但缺少来源不等于未登录。无法读取已关闭页面的存储，不导出 IndexedDB 或浏览器指纹，无法保证平台不要求跨设备验证。文件是登录凭证，请妥善保管。手机浏览器不在支持范围内。

旧版用户需要重新下载并加载扩展，确认版本为 1.2.0 后重新导出；旧 JSON 无法补回此前未导出的数据。

旧 Mac / Windows 下载地址仍可用，现在统一提供免依赖扩展包。仓库原 Python 脚本保留供开发使用，不再作为普通用户的下载工具。

## 预测说明

已接入 **LightGBM 分类 + 分位数回归**，配合按时间分离的 Sigmoid 概率校准和区间扩展校准。默认每日后台检查训练，全服务器使用持久化 FIFO 队列，同一时间最多运行一个账号的训练与回测（管理员也参与该队列），单次训练 CPU 最多使用 2 个计算线程；也可在「预测中心」点击「训练并回测」。模型与数据都保存在这台 Mac，不请求外部模型或价格 API。

- 预测目标：从次日起 `forecast_days` 个自然日中，**同商品 / 同 SKU / 同价格口径观测到的最低价**，以及较当前价下降至少 `drop_threshold` 的概率。默认 14 天、3%。未被爬虫捕获的短时优惠不在可验证范围内。
- 数据按上海时区汇总为日级收盘价和当日观测最低价；普通价、补贴价、券后价、会员价分开建序列。有效人工录入、按天补录和修正价按真实价格参与训练，权重与采集价一致；原始金额保留用于审计，不会和修正价重复计入。同日重复编辑不增加日级样本数，撤销后恢复原值。失败不插值；自动采集未核验 SKU、无效、缺货或明确排除预测的记录不进入训练，所有记录均须有明确商品 / SKU 身份。商品属性随采集冻结，避免后来编辑影响历史特征。
- 单个监控商品的训练序列按「淘宝商品 ID + SKU ID + 价格口径」识别，名称不参与归组。自动采集需要核验 SKU；人工录入或修正价归入明确指定的目标 SKU，原始采集的冲突证据保留在诊断中。链接没有 `skuId` 时使用页面实际识别并核验的 SKU；不同默认选项分别积累，无法确认身份的价格不进入训练。后来在链接补上相同 SKU 不会丢失此前已核验的历史。不同店铺的 SKU 编号无需相同，同款价差特征则需要统一填写型号、容量和版本规格；缺少这些字段仍可积累自身价格序列。
- 特征包括历史涨跌、价格分位、波动、变价间隔、观测覆盖、型号/规格匹配后的店铺价差、已知活动距离、品牌、品类与容量等。缺少型号/规格时不推测同款店铺关系。
- 成熟标签要求完整走完窗口、未来至少 70% 的自然日有有效观测，且没有超过 3 天的连续缺口；不满足的窗口为未知，不作为未降价样本。
- 初始训练最低要求：240 个成熟样本、90 个成熟决策日、降价与未降价样本各 30 个、至少 2 条 SKU / 价格口径序列。达到门槛也不等于验证通过。
- 至少 2 个独立时间回测块；训练、校准、测试之间排除互相重叠的未来标签窗口。回测至少 60 个样本、28 天（长窗口还需至少两倍窗口天数）、正负各 10 个样本。概率误差须优于历史发生率与不降价基线至少 2%，并通过校准误差门槛；最低价模型须优于价格不变基线至少 2%，区间回测覆盖率至少 75%，且宽度受限。概率与区间分别验收。
- 区间显示为“目标 80% 覆盖”，同时展示实测覆盖率；不承诺未来必然覆盖 80%。数据不足、候选未通过、模型过期或文件损坏时，不产生虚构概率；可用的旧模型仍可使用，否则退回 `rules-v2`。

训练排队会显示本账号的位置及提交时间，重复点击不增加任务。重启后排队请求继续执行，停用账号的未开始请求取消；取消页面等待不会提前释放实际训练占用的名额。

「预测中心」会显示积累进度、最近训练结果、基线对比、概率分组与实际降价率，并提供 JSON 验证报告。模型存于 `data/forecast-models/`，采用原生模型文本和 JSON 元数据，文件校验后才加载；版本与目标设置需一致，历史人工修正后需重新训练，有效期 30 天。

保留原有影子模式设置：开启时记录和展示已验证模型的概率、区间及建议，主标签继续采用规则；关闭后才由已验证模型接管标签。规则阶段按日级价格计算分位，并保持失败打断变价确认。人工临时标签覆盖只影响展示。

每次预测保存当时窗口、阈值、SKU 和价格口径，走完窗口后用实际观测回顾；后续改阈值不会重写过去的判断。回顾最低价差是事后统计，不代表可实现的购买收益。数据库备份不包含可重训的模型文件，恢复数据后会自动重新积累 / 训练。

模型依赖由启动脚本安装。若新 Mac 的 LightGBM 提示缺少 `libomp`，可通过 Homebrew 安装：`brew install libomp`。

## 统一价格使用规则

同一商品、SKU、价格口径及北京时间日期只使用统一的生效价格。优先级为：按天人工编辑 > 单条价格人工修正 > 手动新增 / 文件导入 > 爬虫与官方 API 采集；同类冲突取最近保存的人工价格。所有入口共用此规则，人工值覆盖当天有效观测的使用值，原始金额和来源保留，可通过撤销恢复。已标无效、缺货或明确排除预测的设置仍生效，不同平台 / SKU / 口径继续分开。训练仅增加一个日级样本，不因同日重复修改或采集而膨胀；历史时点计算不会使用之后才观测到的手工价格。

## 未填写链接的参考历史

可以先按名称、型号和规格建立参考商品，链接留空时始终暂停，不会打开采集浏览器。历史表格未注明店铺、淘宝 SKU 或价格口径时，使用独立的 reference 序列，不伪造商品 ID。图表和每日价格完整展示；人工导入历史（包括 measured 与 carried_forward 来源标记）与爬虫价格同等用于展示、统计、特征与未来标签；来源标记只用于追溯，不按来源降低训练权重。原文件名、原表位置和数据性质随价格保留。后续编辑商品补上淘宝链接，系统 ID 与参考历史不变，实际 SKU 和各价格口径分别积累。

## CSV 导入与导出

在导入窗口下载对应的 CSV 空白模板和完整格式说明。详见 [CSV 格式规范](docs/CSV_FORMAT.md)。CSV 使用 UTF-8、固定英文列名，空库导出也保留表头；数组填写 JSON，布尔值为 true / false。商品链接保留淘宝 id 和 skuId，商品导入后默认暂停。

历史价格必填 `product_id,observed_at,price,price_unit`：product_id 来自商品清单导出的系统 ID，时间带时区，price_unit 为 yuan（元）或 cent（分）。导出金额统一为整数分。不同 SKU 和普通价 / 补贴价 / 券后价 / 会员价分别保存；有效人工导入作为真实价格参与训练。CSV 用于新增和数据交换，完整恢复请使用数据库备份。

## 备份与恢复

设置中可立即备份或配置每日备份。保存在 `data/backups/`，使用 SQLite Backup API，默认保留 7 份。超过配置期限的日志、价格观测和回收站对象会自动清理，清理前确保已有备份。

```sh
.venv/bin/python run.py --stop
.venv/bin/python restore_backup.py data/backups/你的备份.sqlite3
.venv/bin/python run.py
```

恢复先校验完整性，拒绝在服务运行时覆盖；覆盖前另存恢复前快照。备份不含 Cookie、访问令牌、通知密钥，恢复后按需重新配置渠道。

## 管理员加密完整备份与恢复

「设置 → 保留与备份」下方的管理员完整备份包含唯一管理员与全部注册账号、用户与目录映射、各用户业务数据库、通知配置、预测模型和公网域名配置。备份使用 Scrypt 派生密钥和 AES-GCM 分段认证加密，密码至少 12 位且不保存到服务器。可选择包含所有账号各自的淘宝 Cookie，默认不包含。只读到已完成的模型文件；不包含旧令牌、网页登录会话和重复备份文件。普通用户不能创建、读取、校验或下载系统完整备份。

完整备份文件存放在 `data/system-backups/*.gdbak`。可以在页面输入密码校验文件，也可在终端仅校验：

```sh
.venv/bin/python restore_backup.py data/system-backups/你的备份.gdbak --full --check-only
```

恢复必须先停止服务，然后在项目目录执行（密码会在终端私密输入，不放在命令参数中）：

```sh
.venv/bin/python run.py --stop
.venv/bin/python restore_backup.py data/system-backups/你的备份.gdbak --full
.venv/bin/python run.py --no-browser
```

先完成密码认证、文件清单与 SHA-256 校验、路径检查、SQLite 完整性检查及用户目录映射检查，全部通过后才替换数据；密码错误、文件损坏和目录越界会拒绝恢复。恢复前数据保存到 `data-before-full-restore-*` 目录，写入失败会回滚。恢复保留账号 ID、密码和用户隔离；所有网页会话退出，各账号自动采集默认暂停，未完成任务重新排队，模型训练请求可继续。未包含 Cookie 时需重新登录或上传，旧项目根目录会话不会自动补入。原有单账号 `.sqlite3` 业务备份和恢复命令继续可用。

## 互斥的爬虫 / 官方 API 价格来源

「设置 → 价格来源」默认选中爬虫，淘宝和京东 API 均关闭。每个账号自行填写官方应用的 AppKey、AppSecret 及接口要求的授权令牌，启用所需平台后选择官方 API 并保存。程序固定请求官方 HTTPS 网关并自动签名，不支持第三方代理接口。

- 自动监测、单件重抓、批量重抓、失败重试、一键采集共用当前来源；API 分支不依赖 Cookie，爬虫分支不会调用 API。切换后等待旧来源在途任务和间隔结束，再启动新来源，两个分支不会同时取价。
- 两个分支共用商品采集周期、事件加频、每账号最多 5 并发、普通账号合计 50 并发、每批结束等待 8 秒和 120 秒任务超时。暂停与熔断只影响自动任务，手动采集优先执行。无链接及当前分支不支持的平台商品会从自动采集和一键采集中跳过。
- 官方 API 没有权限、超额、未返回商品或请求失败时返回 `None` / `null`，日志和弹窗显示官方错误，不切换到爬虫。应用凭证各账号隔离，Secret / Token 不回显、不写入日志；普通业务备份清除 API 凭证并切回爬虫，管理员的密码加密完整备份会保留全部 API 配置。
- 淘宝支持 [`taobao.tbk.item.info.get`](https://developer.alibaba.com/docs/api.htm?apiId=24518) 和 [`taobao.item.sku.get`](https://developer.alibaba.com/docs/api.htm?apiId=28)。前者读取 `zk_final_price` 商品级折扣价，没有 SKU 核验信息；带 `skuId` 的链接返回 `api_sku_unsupported`，不拿商品级价格代替规格价。后者需要卖家授权和相应应用权限，核对 `num_iid` 与 `sku_id` 后读取 SKU 标价 `price`，仅限接口授权范围。
- 京东支持联盟的 `jd.union.open.goods.promotiongoodsinfo.query`（`unitPrice`）和 `jd.union.open.goods.query`（`priceInfo.price`），核对返回 SKU。使用 `https://item.jd.com/数字SKU.html` 或移动端完整详情链接；官方接口的商品覆盖范围及额度以应用权限为准。[京东官方文档](https://union.jd.com/openplatform)、[京东官方网关与签名说明](https://open.healthjd.com/docs/接入指南/开放平台-调用API/)。
- API 价格在历史中显示「淘宝 API / 京东 API」，与爬虫价格同等用于展示、统计、提醒和模型训练，人工价格继续优先。训练仍要求明确的商品、SKU 和价格口径；淘宝商品级价格只展示，不进入 SKU 模型。京东与淘宝使用不同的平台身份，不会因数字 ID 相同而混用数据。
